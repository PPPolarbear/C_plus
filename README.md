## 每日文件的六段结构

| 段 | 作用 |
|---|---|
| **⚡ 现在就开始** | 一条命令 / 一个动作，60 秒进入状态 |
| **🎯 今天唯一的目标** | 一句话，今天只为这件事 |
| **📖 读** | 具体章节，**只读这些** |
| **✍️ 写** | 函数签名 / 具体任务，**照做就行** |
| **✅ 验收** | 打勾才算过 |
| **🔜 明天** | 预告，不用现在管 |

---

## 四条铁律

1. **验收没全打勾，不进下一天。** 后面的内容建立在前面的正确性上。
2. **卡住超过 40 分钟就跳过。** 标记下来继续走，回头看往往突然就懂了。
3. **不要提前读后面的 Day。** 每天的"读"刚好够用，多读会淹没你。
4. **写不出来就让它先编译通过。** 能跑 > 完美。

---

## 落后了怎么办

| 情况 | 处理 |
|---|---|
| 落后 1–2 天 | 正常，继续按顺序走 |
| 落后 3 天以上 | 砍掉 Day 54（工程化），那个可以后补 |
| 某天卡死超过 2 天 | **跳过，标记，继续往前** |

**落后是常态。** 57 天是节奏，不是 deadline。
