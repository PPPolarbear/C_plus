## 🎯 这一份解决什么问题

你学 CMake 时它是"黑盒"——**CMake 到底生成了什么？** 答案就是 Makefile。

理解了 Makefile，你就理解了：
- 为什么改了 `.cpp` 只重编那一个文件（**增量构建**）
- 为什么"加文件要手动改配置"（**依赖关系是显式声明的**）
- CMake 帮你省掉了什么麻烦

**这不是必须会的技能**（有 CMake 就够了），但它让你从"会用工具"变成"懂工具"。

## 一、Makefile 是什么

**一个"如何编译这个项目"的说明书。**

CMake 和 Makefile 的关系：

```
CMakeLists.txt  ──CMake──▶  Makefile  ──make──▶  可执行文件
   你写的                  自动生成的             你真正要的
   （跨平台）              （平台相关）
```

- **Makefile**：能干活，但换个平台就要重写
- **CMake**：你只写一份，它帮你生成对应平台的 Makefile

**所以 CMake 出现在 Makefile 之后，是为了解决"跨平台"这个问题。**

---

## 二、最小可以工作的 Makefile

建一个 `hello.cpp`：

```cpp
#include <iostream>
int main() { std::cout << "hello make\n"; }
```

建一个 `Makefile`（**注意文件名大写 M、没有扩展名**）：

```makefile
app: hello.cpp
	g++ -std=c++17 -o app hello.cpp
```

**⚠️ 关键**：第二行开头必须是 **Tab 键**，不能用空格！这是 Makefile 最著名的坑。

```bash
make          # 执行
./app         # 运行
```

## 三、逐行拆解

```makefile
app: hello.cpp
	g++ -std=c++17 -o app hello.cpp
```

```
app        :  hello.cpp
 ↑              ↑
目标(target)   依赖(prerequisites)
		g++ ...
        ↑
    配方(recipe)  ← 必须 Tab 开头
```

**读法**：**"要生成 `app`，需要先有 `hello.cpp`。如果 hello.cpp 比 app 新，就执行下面的命令。"**

**这就是增量构建的原理**——make 比较时间戳，只在必要时才重编。

### 验证增量构建

```bash
make          # 第一次：真的编译
make          # 第二次：输出 "make: 'app' is up to date."（什么都没做）
touch hello.cpp   # 假装改过文件（更新修改时间）
make          # 又编译了一次
```

**这就是为什么改一个文件只重编一个——make 在比较时间戳。**

## 四、变量与自动变量

```makefile
CXX      = g++
CXXFLAGS = -std=c++17 -Wall -O2

app: hello.cpp
	$(CXX) $(CXXFLAGS) -o app hello.cpp
```

| 写法 | 含义 |
|---|---|
| `CXX = g++` | 定义变量 |
| `$(CXX)` | 使用变量 |
| `=` | 延迟展开（用到时才求值） |
| `:=` | 立即展开 |
| `?=` | 没定义过才定义 |

**自动变量**（在配方里用）：

| 变量 | 含义 |
|---|---|
| `$@` | **目标**名（`app`） |
| `$<` | **第一个**依赖（`hello.cpp`） |
| `$^` | **所有**依赖，去重 |
| `$?` | 比目标新的那些依赖 |

用了自动变量，配方就通用了：

```makefile
app: hello.cpp
	$(CXX) $(CXXFLAGS) -o $@ $^
```

## 五、多文件：显式的依赖关系

**这就是"加文件要手动改配置"的来源。**

```
main.cpp
math_utils.cpp
string_utils.cpp
```

```makefile
CXX      = g++
CXXFLAGS = -std=c++17 -Wall

app: main.o math_utils.o string_utils.o
	$(CXX) $(CXXFLAGS) -o $@ $^

main.o:         main.cpp math_utils.h
	$(CXX) $(CXXFLAGS) -c $< -o $@

math_utils.o:   math_utils.cpp math_utils.h
	$(CXX) $(CXXFLAGS) -c $< -o $@

string_utils.o: string_utils.cpp string_utils.h
	$(CXX) $(CXXFLAGS) -c $< -o $@

clean:
	rm -f *.o app
```

```bash
make          # 编译
make clean    # 清理
```

**看明白什么了？**

- 每个 `.cpp` 单独编译成 `.o`（**目标文件**）
- 最后把 `.o` 链接成 `app`
- **`main.o` 依赖 `math_utils.h`** —— 改了头文件，所有 include 它的文件都要重编

**新增一个文件？必须手动加一行。** 这就是为什么 CMake 里也要手动 `add_executable`——**依赖关系必须显式声明，没有"自动发现"这回事。**

## 六、模式规则（少写重复）

上面三段 `.o` 规则长得几乎一样，可以用模式规则压缩：

```makefile
CXX      = g++
CXXFLAGS = -std=c++17 -Wall

SRCS = main.cpp math_utils.cpp string_utils.cpp
OBJS = $(SRCS:.cpp=.o)          # 把 .cpp 替换成 .o

app: $(OBJS)
	$(CXX) $(CXXFLAGS) -o $@ $^

# 模式规则：所有 .o 都由对应的 .cpp 生成
%.o: %.cpp
	$(CXX) $(CXXFLAGS) -c $< -o $@

clean:
	rm -f $(OBJS) app
```

| 符号 | 含义 |
|---|---|
| `%.o` | 匹配任意 `.o` 文件 |
| `$(SRCS:.cpp=.o)` | 字符串替换：把 `.cpp` 换成 `.o` |
| `$<` | 第一个依赖（对应的 `.cpp`） |

**这已经接近 CMake 生成出来的 Makefile 了。**

## 七、特殊目标

```makefile
.PHONY: clean all test
```

**`.PHONY` 声明"这不是真实文件"**。

为什么需要：如果目录里恰好有个叫 `clean` 的文件，`make clean` 会以为"已经是最新的了"而不执行。加了 `.PHONY` 就总是执行。

```makefile
all: app test          # make 不带参数时，默认执行第一个目标
clean:                 # 清理
test:                  # 跑测试
install:               # 安装
```

**约定俗成的目标名**：`all` / `clean` / `test` / `install`。

## 八、看一眼 CMake 生成的 Makefile

回到你的训练营项目：

```bash
cd cpp-camp          # 你 Day 01 建的项目
cmake -B build
ls build/
```

你会看到 `Makefile`、`CMakeCache.txt`、`CMakeFiles/` 等。

```bash
less build/Makefile          # 看开头，注释里会写 "Generated by CMake"
less build/CMakeFiles/app.dir/build.make    # 真正的编译规则在这
```

**对比一下**：CMake 生成的 Makefile 有几百上千行，还带了大量跨平台处理。**你手写的那 10 行，就是它的核心。**

## 🤔 卡住了怎么办

| 症状 | 解法 |
|---|---|
| `missing separator` | **配方行用了空格，必须改成 Tab** |
| `No rule to make target` | 依赖写错了，或文件不存在 |
| `make: 'app' is up to date.` | 正常，没东西要重编。`touch` 一下源文件 |
| `clean` 不执行 | 目录里有个叫 `clean` 的文件，加 `.PHONY` |
| 想看 make 到底执行了什么 | `make -n`（只打印不执行） |

> **Tab 问题**：VS Code 里打开 Makefile，右下角把它设成 "Indent Using Tabs"。有些编辑器会自动把 Tab 转成空格，这会让 Makefile 直接坏掉。
