# 01 · 命令行进阶

> **适用**：会用 `ls` / `cd` / `cp` / `mv` / `rm`，但 `grep` / `find` / 管道 / 重定向 不熟。
> **读 + 练约 1.5 小时。**

---

## ⚡ 现在就开始

```bash
echo "hello" | grep "ell"
```

能输出 `hello`，说明你在一个正常的 shell 里。往下。

---

## 🎯 这一份解决什么问题

**命令行的威力不在单个命令，而在"把命令串起来"。**

会 `ls` 和会 `ls | grep .cpp | wc -l` 是两个层次。后者让你一句话回答"这个目录有多少个 cpp 文件"。

57 天里你会反复用到：**过滤 valgrind 的输出、统计代码行数、批量找文件**。

---

## 一、管道 `|`（最重要）

**把左边命令的"输出"，当成右边命令的"输入"。**

```bash
ls                    # 列出所有文件
ls | grep ".cpp"      # 只保留含 ".cpp" 的行
ls | grep ".cpp" | wc -l   # 数一数有几行
```

拆开看：

```
ls  ──输出──▶  grep ".cpp"  ──输出──▶  wc -l  ──输出──▶ 屏幕
```

**管道可以无限串联。** 这是命令行的核心思维方式：**每个命令只做一件事，靠管道组合。**

---

## 二、三个必会的过滤器

### `grep` —— 从文本里挑出符合条件的行

```bash
grep "error" log.txt              # 显示含 error 的行
grep -i "error" log.txt           # 忽略大小写
grep -n "error" log.txt           # 显示行号
grep -v "error" log.txt           # 反向：显示【不含】error 的行
grep -r "TODO" ./src              # 递归搜索整个目录
grep -c "error" log.txt           # 只输出匹配的行数
```

`-r` 是**最常用的**——在项目里找某个函数在哪定义过。

### `wc` —— 数数

```bash
wc -l file.txt      # 行数
wc -w file.txt      # 词数
wc -c file.txt      # 字节数
```

### `sort` / `uniq` —— 排序去重

```bash
sort file.txt             # 排序
sort file.txt | uniq      # 去重（必须先排序）
sort file.txt | uniq -c   # 去重并统计每种出现几次
sort -n numbers.txt       # 按数字排序（不是字典序）
```

## 三、重定向 `>` `>>` `2>`

### 输出重定向

| 写法 | 作用 |
|---|---|
| `cmd > file` | 输出**覆盖**写入 file |
| `cmd >> file` | 输出**追加**到 file 末尾 |
| `cmd > /dev/null` | 丢弃输出（垃圾桶） |

```bash
echo "hello" > a.txt      # a.txt 现在是 "hello"
echo "world" >> a.txt     # a.txt 现在是两行
```

### ⚠️ 错误输出要去哪？

**这是新手最容易踩的坑**：`>` 只重定向"标准输出"，**报错走的是"标准错误"，不会被重定向！**

```bash
./program > out.txt        # 报错还是会打到屏幕上
./program > out.txt 2>&1   # ✅ 报错也写进文件
```

`2>&1` 的意思：**把 2 号流（标准错误）也指向 1 号流（标准输出）当前指向的地方。**

在 57 天里你会大量用到，比如把 valgrind 的输出存下来：

```bash
valgrind ./app > vg.log 2>&1
```

### `tee` —— 既写文件又打屏幕

```bash
./app | tee out.txt        # 输出同时到屏幕和文件
```

## 四、`find` —— 找文件

`grep` 搜**文件内容**，`find` 搜**文件名**。别搞混。

```bash
find . -name "*.cpp"                    # 当前目录下所有 .cpp
find . -name "*.h" -o -name "*.hpp"     # 找 .h 或 .hpp（-o = or）
find . -type d -name "build"            # 只找目录
find . -type f -size +1M                # 大于 1MB 的文件
find . -name "*.log" -delete            # 找到并删除
```

**57 天里最常用的一条**：

```bash
find . -name "*.cpp" -o -name "*.h" | xargs wc -l | tail -1
```
→ 统计整个项目的代码行数。（`xargs` 把前面的结果"喂"给后面的命令）

## 五、组合技：把上面全串起来

### 场景 1：找某个函数在哪定义

```bash
grep -rn "MyVector" ./include
```

### 场景 2：统计项目有多少行代码

```bash
find . -name "*.cpp" -o -name "*.h" | xargs wc -l
```

### 场景 3：从 valgrind 输出里挑出关键行

```bash
valgrind ./app 2>&1 | grep -E "lost|Invalid|ERROR"
```
（`-E` 开启扩展正则，`|` 在引号里表示"或"）

### 场景 4：看编译错误里有多少个

```bash
cmake --build build 2>&1 | grep -c "error"
```

### 场景 5：找出所有 TODO

```bash
grep -rn "TODO" . --include="*.cpp" --include="*.h"
```

## 六、其他高频命令

| 命令 | 作用 | 例子 |
|---|---|---|
| `head -n 20 f` | 看前 20 行 | `valgrind ... \| head -40` |
| `tail -n 20 f` | 看后 20 行 | `tail -f log.txt`（实时跟踪） |
| `less f` | 分页查看（`q` 退出，`/` 搜索） | 看长文件 |
| `cat f` | 全部打印 | 短文件 |
| `which cmd` | 命令装在哪 | `which cmake` |
| `history` | 历史命令 | `history \| grep cmake` |
| `!!` | 重复上一条命令 | `sudo !!` |
| `Ctrl+R` | **反向搜索历史命令** | **必学，最省时间** |
| `Ctrl+C` | 中断当前命令 | 程序卡住时 |
| `Ctrl+D` | 结束输入 / 退出 shell | — |

## 七、一个小脚本（体会"串起来"的威力）

```bash
#!/bin/bash
# count_lines.sh —— 统计当前目录的 C++ 代码行数

total=0
for file in $(find . -name "*.cpp" -o -name "*.h"); do
    n=$(wc -l < "$file")
    total=$((total + n))
done
echo "总行数: $total"
```

```bash
chmod +x count_lines.sh
./count_lines.sh
```

> `chmod +x` 是给文件加"可执行"权限——这是 Linux 权限系统的入门。你已经会用了跳过即可。

## 🤔 卡住了怎么办

| 症状 | 解法 |
|---|---|
| `grep: 参数列表过长` | 配 `find ... -exec` 或 `xargs` |
| 重定向后报错还在屏幕上 | 忘了 `2>&1` |
| `uniq` 没起作用 | 必须先 `sort` 再 `uniq` |
| Windows 路径反斜杠报错 | MINGW64 里用正斜杠 `/d/AI/...` |
| 管道符在引号里 | `grep -E "a\|b"` 表示"a 或 b"，不是管道 |
